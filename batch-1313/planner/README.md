# Full clump planning and saved-plan application

The original community tool and two revisions of the PR tool ran in fresh Python processes on one Ubuntu runner. Each tool received one warm-up and five scored trials. The first tool rotated between rounds. Every process used the same 59,869-file Git checkout and the same exclusion file. The two PR tools produced identical planner output, a 204-clump plan and identical rendered files. All three recovered the same 666 original members and restored the checkout. [Original timed runner ZIP](github-artifact.zip) · [Source and medians](current-timing.json) · [All paired observations and regressions](paired-trials.json)

The community tool applied the plan in 17.046 seconds and used 3,573,882,880 bytes of peak resident memory. The final tool took 0.313 seconds and used 72,617,984 bytes. Both elapsed time and peak memory fell in all five pairs. The preceding PR implementation already reads only the selected members for apply. The final implementation was slower in three of five apply pairs against that version. Its planning improvement reduced peak memory from 3,740,004,352 to 735,764,480 bytes and the median planning time from 20.281 to 19.222 seconds. [Paired results](paired-trials.json)

An earlier run on this same current checkout completed all 30 timed observations. Its post-timing output check still expected the old batch’s 656 members. The successful run reads the count from the independently checked plan. The earlier observations and failed workflow remain available for comparison.
